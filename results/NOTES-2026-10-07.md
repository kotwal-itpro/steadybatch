# First live runs, 2026-10-07

Four runs of 100 synthetic support tickets each (`examples/make_synthetic.py --n 2000`, seed 2026, first 100 records),
JSON Schema `examples/support_ticket.schema.json`, `max_tokens` 300, temperature 0.

| Run | Field definitions | Notes |
|---|---|---|
| openai gpt-4.1-mini, v1 | none | 100/100 OK, no retries |
| gemini gemini-3.5-flash-lite, v1 | none | 100/100 OK, no retries |
| openai gpt-4.1-mini, v2 | `examples/support_ticket.instructions.txt` | 100/100 OK, no retries |
| gemini gemini-3.5-flash-lite, v2 | `examples/support_ticket.instructions.txt` | 100/100 OK, no retries |

What we saw:

- Both services returned every line, all valid JSON, with no retries, at 100 records.
- Batch turnaround was 1.5 to 3.5 minutes per batch.
- Without field definitions, `sentiment` and `needs_follow_up` accuracy was low on both
  (64-74% and 31%); the models answered a different question than our labels asked
  (see docs/FINDINGS.md, finding 3). With definitions: OpenAI 95% / 99%, Gemini 84% / 100%.
- Token counts for the same records differ a lot between providers
  (v2 input: OpenAI 33,537, Gemini 25,700; output: OpenAI 2,221, Gemini 3,987).
- Cost is not computed yet: per-token prices will be recorded with their date before cost
  figures are published.
- A first attempt on gemini-2.5-flash-lite was rejected at submit time (finding 1) and is not included.

These are small smoke-test runs. The study's real measurements start at 1,000 records,
three runs per provider on different days.
